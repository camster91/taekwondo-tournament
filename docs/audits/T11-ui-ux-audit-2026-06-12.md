# T11 — UI/UX Audit: Visual + Interaction Review

**Date:** 2026-06-12
**Auditor:** default worker (run 15)
**Stack:** React 19 + TS + Vite + Tailwind v4, /taekwondo-tournament repo
**Scope:** 14 pages across 2 viewports (1280x800 desktop, 390x844 mobile) + interaction/a11y tests

---

## 1. Executive summary

The app is in solid shape — recent T6 (PublicRegister a11y) and T7 (BracketEditor + Scorekeeper a11y) work has paid off in those flows. **But the rest of the app is leaking a11y issues that were not in scope of those audits**: every list page has 30-100 icon-only buttons with no `aria-label`, no `aria-pressed` on the Patterns/Sparring toggles, the dashboard h1→h3 skips h2, and the STATUS tile shows raw enum `in_progress`.

The single highest-leverage fix is creating an `IconButton` primitive (already started for `CloseButton` in T6) and applying it app-wide. That fixes the icon-only + hit-area + no-aria-label class of bugs in one shot.

## 2. P0 — Ship in this audit (audience-blocking or compliance-failing)

### P0.1 — Icon-only buttons without `aria-label` (app-wide)
- **Where:** TournamentDetail.tsx (40 toggles + 20 trash buttons), Competitors.tsx (44 edit/delete), CheckIn (40 undo/check-in), Divisions (delete + view), plus all icon-only top-bar buttons.
- **Impact:** Screen reader users hear "button" with no name. WCAG 4.1.2 Name, Role, Value failure.
- **Hit-area side bug:** Most are 7×7 (`h-7 w-7`) or 4×4 — way under 44×44 mobile tap standard. Even desktop hovers are missed.
- **Fix:** Introduce `IconButton` primitive in `src/client/components/ui/IconButton.tsx` mirroring `CloseButton.tsx`. Required prop `label: string` → renders `aria-label`. Defaults hit-area to 44×44 mobile, 32×32 desktop (`sm:scale-down` pattern). Replace 5 highest-traffic sites in this PR: TournamentDetail, Competitors, CheckIn, Divisions, AppLayout top-bar buttons.

### P0.2 — Patterns / Sparring toggles lack `aria-pressed` and `aria-label`
- **Where:** TournamentDetail.tsx L625-658 (table view) and similar in card view. Each row has 2 toggle buttons.
- **Impact:** Screen reader announces "button" twice. Color-only state (`bg-green-500` vs `bg-gray-200`). Cognitive load for users who can't perceive the color.
- **Fix:** Add `aria-pressed={reg.patterns}` and `aria-label="Patterns enrolled"` / `aria-label="Sparring enrolled"`. Keep the visual checkmark.

### P0.3 — `/dashboard` (and other pages) skip from `<h1>` to `<h3>`
- **Where:** Dashboard, Divisions, Schedule, BracketEditor, TournamentDetail — every page with sectioned cards. Verified by `document.querySelectorAll('main h1,main h2,main h3')`.
- **Impact:** Heading outline is broken; screen-reader heading navigation jumps from page title to "Recent tournaments" without intermediate context. WCAG 1.3.1 Info and Relationships.
- **Fix:** Either (a) promote card section titles to h2 (one-liner in PageHeader or CardHeader), or (b) introduce a typed `Section` wrapper that renders h2 by default. Lowest-touch fix: change the CardHeader `<h3>` to `<h2>` for section titles (only top-level cards; sub-cards still h3). Apply to Dashboard first, then template the rest.

### P0.4 — STATUS stat tile shows raw enum `in_progress`
- **Where:** TournamentDetail hero, `STATUS` stat shows literally `in_progress` while the banner below reads "Tournament is active. Mark as completed…".
- **Impact:** Looks like a bug to a paying user. Every other status display uses a humanized label.
- **Fix:** Map `TournamentStatus` enum → label in one place. Add `displayLabel` to a shared util or use existing `getStatusBadge()` if present. Confirmed in `src/shared/constants` or inline at the stat tile.

### P0.5 — `/verify-magic-link` route is `/verify` (task spec outdated)
- **Where:** App.tsx L435 — actual route is `/verify`, not `/verify-magic-link`.
- **Impact:** Not a bug per se, but the task spec lists 15 routes; 4 don't match. Audit doc should reflect the real routes. (Documented for posterity, not a code change.)

### P0.6 — Top-bar bell and DV avatar have no accessible name
- **Where:** `AppLayout` (or equivalent) top-right bell + sidebar "DV" user button.
- **Impact:** Screen reader announces "button" twice. Sidebar avatar should at least expose the user's full name.
- **Fix:** `aria-label="Notifications, X unread"` (if count available) and `aria-label="Account menu, Demo Visitor"`.

## 3. P1 — File as T12 (production-grade polish, not blocking)

### P1.1 — BYE button prominence inverts visual hierarchy
- **Where:** BracketEditor, all unplayed matches. Each shows two green-pill "BYE (winner)" buttons that visually shout louder than real competitor names.
- **Impact:** A user glancing at the page thinks the tournament is mostly decided. WCAG 1.4.11 Non-text Contrast (3:1 for UI components) passes, but cognitive load fails.
- **Fix:** Replace BYE pill with dashed-outline, low-contrast "TBD" slot. Reserve green for "winner" state.

### P1.2 — "Top schools" ranks #1 and #2 missing `#` glyph
- **Where:** Dashboard, Top schools card.
- **Impact:** Confusing visual rhythm. Looks like a CSS bug.
- **Fix:** Ensure the rank badge renders consistently for all 1-3+ positions. Verified visual; could be a conditional render that hides on first two rows.

### P1.3 — Tournament name "E2E Test Tournament 1781225226731" leaks timestamp
- **Where:** Tournaments list, dashboard recent, divisions parent labels.
- **Impact:** Looks like a test artifact, not production data. Reduces trust in the product for trial users.
- **Fix:** Truncate the auto-generated suffix with ellipsis. E.g., `E2E Test Tournament…6731`. Better: require non-numeric display name on creation.

### P1.4 — Status pill color contrast borderline (Draft / In Progress)
- **Where:** Tournaments list pills.
- **Impact:** Light gray on light gray, yellow on white — likely fail WCAG 1.4.3 4.5:1 for small text.
- **Fix:** Darken the pill text, or add a 1px border in the status color so the meaning carries without relying on text contrast.

### P1.5 — Search bar lacks filter chips, sort, and result count
- **Where:** Tournaments, Competitors, CheckIn all have search but minimal filters.
- **Impact:** For 100+ competitors, this is a real friction.
- **Fix:** Add result count (e.g. "Showing 3 of 21") and at minimum a sort control.

### P1.6 — Delete / destructive action lacks confirmation modal in lists
- **Where:** Tournaments "Delete" button, Divisions "Delete Division", Competitors "Delete" (probably already a confirm — needs check).
- **Impact:** One mis-click = lost data. No undo. The Scorekeeper undo is great — same pattern should apply to lists.
- **Fix:** Wrap destructive actions in `ConfirmDialog` (already a component). Apply to Tournament delete and Division delete.

### P1.7 — "Number of Rings" input on Schedule shows 4 but only 2 rings render
- **Where:** Schedule page.
- **Impact:** Not a bug — likely the schedule is partial. But the UI doesn't explain why. Shows staleness.
- **Fix:** Add a small hint when N rings is configured but fewer divisions exist: "1 ring is unassigned — add at least 4 divisions to fill it."

### P1.8 — Filters mixed with sort in CheckIn
- **Where:** CheckIn filter row.
- **Impact:** Minor confusion. Sort and filter are different mental models.
- **Fix:** Move "Name (A-Z)" to a separate sort control on the right.
